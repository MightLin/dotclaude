# Skill：撰寫 business-logic.md

## 目的

讓 Claude 理解專案的業務領域知識，避免產出技術上正確但業務上錯誤的程式碼。

## 必要內容

### 1. 名詞定義

專案特有的領域術語，一詞一義，避免歧義。

### 2. 核心業務流程

重要流程的狀態流轉，用簡單的文字或箭頭表示：
`狀態A → 觸發條件 → 狀態B`

### 3. 業務規則與限制

明確的判斷條件，格式：
`- 當 {條件} 時，{允許/禁止} {操作}`

### 4. 特殊計算邏輯

非直覺的計算方式或公式，說明原因。

## 範例

```markdown
# Business Logic

最後更新：YYYY-MM-DD

## 名詞定義

- 工單：一筆模具製作或維修的需求單
- 里程碑：工單執行過程中的關鍵節點

## 核心業務流程

工單狀態：草稿 → 送審 → 核准 → 進行中 → 結案

- 草稿：僅建立者可編輯
- 送審：鎖定編輯，等待主管核准
- 核准後：自動建立 OpenProject Work Package
- 結案：需附上完工照片才可執行

## 業務規則

- 當工單狀態為「進行中」時，禁止修改預算欄位
- 當里程碑逾期超過 3 天，自動發送通知給負責人
- 同一模具同時只能有一筆進行中的工單

## 特殊計算

- 工單總工時：加總所有子任務工時，不含假日
```
